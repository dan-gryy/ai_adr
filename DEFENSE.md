# 1. Намір і критерії
Побудова концептуальної моделі для C++ месенджера EchoLink. Ключові критерії: 3NF, використання виключно UUID, та декларативний опис M:N зв'язків без передчасної прив'язки до реляційних сполучних таблиць SQLite.


# 2. Топ-3 розбіжності
Під час генерації (див. `ai/prompts.md`) знайдено помилки ШІ, які виправлено оновленням критеріїв у `spec.md` (коміт `fix(model): enforce UUID, pure M:N...`):
1. **Типи даних:** Згенеровано `Int` замість `UUID`.
2. **Зайва сутність:** Згенеровано фізичну сполучну таблицю `User_ChatRoom`.
3. **Неймінг FK:** Зовнішній ключ названо `room` замість `room_id`.


# 3. Ключове рішення
Використання декларативного зв'язку `}o--o{` між User та ChatRoom замість таблиці-зв'язки на етапі концептуального проєктування. Деталі див. у `adr/001-mn-relation.md`.


# 4. Перевірка
Узгодженість перевірено шляхом зіставлення фінального коду Mermaid із критеріями `spec.md`. Рендер показує `}o--o{` без додаткових сутностей, усі поля містять `UUID`.
