# Історія генерації моделі EchoLink за допомогою AI

## Спроба 1 (Початковий запит)
**Промт:** Згенеруй концептуальну ER-модель для клієнт-серверного месенджера EchoLink. Сутності: User, ChatRoom, Message.
**Аудит (Помилка AI):** ШІ використав цілочисельні (Int) типи даних для первинних ключів.
**Рішення:** Додати суворий критерій щодо використання UUID у `spec.md`.

## Спроба 2 (Після уточнення ключів)
**Промт:** Перегенеруй модель. Всі ідентифікатори (PK та FK) повинні мати тип UUID.
**Аудит (Помилка AI):** ШІ створив фізичну сполучну таблицю `User_ChatRoom` для зв'язку учасників із кімнатами.
**Рішення:** Додати критерій у `spec.md`, що вимагає використання чистого M:N зв'язку (без проміжних таблиць) для концептуальної моделі.

## Спроба 3 (Після заборони фізичних таблиць)
**Промт:** Прибери таблицю User_ChatRoom. Зроби прямий концептуальний зв'язок багато-до-багатьох між User та ChatRoom.
**Аудит (Помилка AI):** ШІ неправильно назвав зовнішній ключ у таблиці Message (назвав `room` замість `room_id`).
**Рішення:** Зафіксувати точні назви FK у критеріях `spec.md` і перегенерувати фінальний варіант.
