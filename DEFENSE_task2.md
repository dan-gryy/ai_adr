# DEFENSE — Завдання 2: Вимоги та Use Cases

**Намір і критерії:**
Проєктування структурованих вимог для термінального C++ месенджера EchoLink. Мета — розібрати вглиб прецедент "Відправка повідомлення" через Gherkin, EARS та кількісні NFR без включення системи як актора.

**Топ-3 розбіжності (spec ↔ артефакт) + коміт-виправлення:**
1. **Актор-система:** ШІ згенерував UC, де "Система" ініціювала розсилку. Виправлено: систему прибрано, розсилку включено в EARS-реакцію.
2. **Синтаксис EARS:** Було If/Then. Виправлено власноруч на `WHEN... SHALL...`.
3. **Абстрактні NFR:** ШІ дав вимоги без меж. Додано: 200 мс, 500 користувачів, TLS 1.2+, термінал 80x24.

**Ключове рішення (ADR):**
Визначення меж сценарію "Відправка повідомлення" (`adr/002-message-delivery.md`). Вирішено не виносити Broadcasting в окремий UC, бо система не є ініціатором.

**Перевірка (узгодженість):**
Актор User на UC-діаграмі відповідає сутності User в ER-модель (Завд. 1). Сценарії Gherkin оперують концептом ChatRoom з БД.
